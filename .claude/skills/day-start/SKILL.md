# 開工（/day-start）

目的：新對話沒有昨天的記憶，開工時把「做到哪、決定了什麼、還有什麼沒收」讀回來，再開始做事。
**這個指令只讀不寫**：不改程式、不 commit、不備份。

## 1. 讀日誌

- 讀 `docs/journal/` 裡日期最新的一份（檔名 `YYYY-MM-DD.md`）；沒有任何日誌就說明「還沒有日誌」，跳過這步。
- 重點抓：「明天從這裡開始」「未完成」兩段。
- 如果最新日誌不是昨天（中間隔了幾天），說明隔了幾天，並用 `git log --since=<日誌日期> --oneline` 補看這段期間有沒有不在日誌裡的 commit。

## 2. 讀判斷點

- 讀 `docs/decisions.md`。
- 列出「待決定」的每一項（這些要使用者拍板，不要自己決定）。
- 「已決定」只在和今天要做的事有關時提一下，例如今天要動請假流程，就提「取消已核准的單要填原因」這類規則。

## 3. 檢查備份源

**git**
- `git status --short`：有沒有沒 commit 的改動（可能是昨天沒收完）。
- `git log origin/master..HEAD --oneline`：有沒有沒 push 的 commit。先 `git fetch` 再比，fetch 失敗（離線）就說明，不要重試。
- `git log -5 --oneline`：最近做了什麼。

**資料庫**
- 列出 `backups/` 裡最新的每日備份（`roster_*.db`、`roster_test_*.db`）與升級前快照（`before_*.db`）的檔名與時間。
- 最新的每日備份超過 1 天就提醒。
- 只看檔名與時間，**不要打開或複製資料庫**（內含員工個資）。

## 4. 輸出開工摘要

用這個格式回報，越短越好：

```
## 開工 YYYY-MM-DD
**上次做到**：（1–3 行，來自日誌）
**今天建議先做**：（來自「明天從這裡開始」，依優先順序）
**待你決定**：（來自 decisions.md 的待決定；沒有就寫「無」）
**備份狀態**：git 未 commit N 檔 / 未 push N 筆；最新 DB 備份 <檔名>（N 小時前）
**注意**：（隔了幾天、有日誌外的 commit、備份太舊等異常；沒有就省略這行）
```

最後問使用者今天要從哪一項開始。
